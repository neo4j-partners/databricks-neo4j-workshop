= Appendix A: GDS Graph Analytics

WARNING: **You cannot run these notebooks on your workshop instance.** Graph Data Science is not available on AuraDB Free, and AuraDB Free is the tier xref:lab1.adoc[Lab 1] puts you on. Every notebook in this appendix fails at its first `gds.` call. **Appendix A is take-home**: read it during the workshop, run it later on an instance that carries the plugin. The workshop's slides teach the concepts, and you can follow them without running any of the algorithms.

The graph you built in Lab 2 answers questions about what is connected to what. Graph algorithms answer a different kind of question: "which aircraft behave like each other", "which airport would hurt most if it closed", and "which faults cluster together across the fleet". Those answers are computed from the shape of the graph rather than read out of it.

.**At a Glance**
* **Three algorithm families**, one folder each: community detection, centrality, and similarity.
* **Every one needs Lab 2 notebook 01** to have loaded the fleet, plus the GDS plugin, which AuraDB Free does not have.
* **GDS runs on a projection.** It copies part of the graph into memory, runs the algorithm there, and writes results back as node properties.
* **The output is a feature.** Each score becomes a node property, and that property becomes a column an ML model in Databricks can train on.

== What Graph Algorithms Compute

A Cypher query traverses the graph you have. A graph algorithm reads the whole structure and computes a value that is not stored anywhere in it.

[cols="1,2,2"]
|===
| Family | The question it answers | Algorithm here

| Community detection
| Which things group together, without anyone labelling the groups
| Louvain

| Centrality
| Which things matter most to the network as a whole
| PageRank, Betweenness

| Similarity
| Which things resemble each other, by what they connect to rather than by their properties
| Node Similarity (Jaccard)
|===

.How a projection works
[%collapsible]
====
GDS runs over a **projection** rather than the stored graph: an in-memory, read-optimised copy holding only the labels and relationship types the algorithm needs. The algorithm runs there, and the results are written back to the stored graph as node properties.

Two things follow from that. A projection is a snapshot, so results reflect the graph as it was when the projection was built. And a projection holds memory until it is dropped, which is why every notebook in this appendix drops its projection at the end.
====

== The Three Notebook Families

**Community detection, Louvain.** Groups aircraft into risk communities from shared fault patterns. Nobody defines the communities in advance; they fall out of which aircraft keep having the same kinds of problems. The useful output is an aircraft that lands in a community whose other members are already failing.

**Centrality, PageRank and Betweenness.** Scores airports by network influence, then finds the ones that act as connectors. The two algorithms rank airports differently on purpose. PageRank finds the busy hubs. Betweenness finds the airports that sit on the paths between everything else. Those are often quiet airports, and they are the ones whose closure breaks the route network into pieces.

**Similarity, Node Similarity with Jaccard.** Finds aircraft sharing overlapping fault portfolios across different models. Two aircraft can be similar without sharing a model, a route or an operator, if the components that fail on them are the same components.

== Why This Belongs in a Databricks Workshop

A community ID, a PageRank score and a similarity neighbour are all numbers on a node once they are written back. Numbers on a node are **features**, and features go back to Databricks to train a model.

That loop runs in both directions. Databricks sends sensor telemetry into the graph. The graph sends back structural features no table could produce, because they describe the connections rather than the rows. A failure-prediction model trained with "how central is this aircraft's usual airport" and "which fault community does it belong to" has information a purely tabular pipeline never had.

**The workshop teaches these slides even though the notebooks are take-home.** Understanding the loop does not require running an algorithm live.
