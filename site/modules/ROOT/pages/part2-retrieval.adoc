= Part 2: Retrieval

Part 1 gave the graph structure. Part 2 gives it text. The maintenance manuals get chunked, embedded and linked back to the graph nodes they describe, so a question can be answered from documentation and topology at once.

.**At a Glance**
* **Chunks and embeddings land in the same graph as the Aircraft Digital Twin.** Document and Chunk nodes sit beside Aircraft and Component, connected rather than stored apart.
* **That connection is what makes it GraphRAG.** Plain vector search returns the chunk. A graph retriever returns the chunk plus the component it names and the maintenance history of that component.
* **Two ways to find a chunk.** Vector search matches by meaning and misses exact strings like `V2500` or `925`. Fulltext search matches by word and catches them. Hybrid search runs both and merges the results.
* **Four retrievers, two search methods times two return shapes.** Notebook 02 builds `VectorRetriever` for plain semantic search and `VectorCypherRetriever` for search plus a traversal. The second is the one Lab 5's agent uses. Notebook 03 adds the hybrid pair, `HybridRetriever` and `HybridCypherRetriever`, if time allows.
* **Embeddings come from Databricks**, the `databricks-bge-large-en` serving endpoint at 1024 dimensions. A fulltext index over the same chunks is what makes the hybrid pair possible.
* **About 45 minutes.**
